# CarMemory 🚗

## Цифровий «мозок» автомобіля

**CarMemory** — це вебзастосунок для зберігання та керування повною історією автомобіля в одному місці.

Ідея проєкту полягає в тому, щоб власнику автомобіля більше не доводилося шукати інформацію по паперових чеках, сервісних книжках, фотографіях у телефоні, повідомленнях від СТО та різних файлах.

CarMemory об'єднує:

- автомобілі користувача;
- історію обслуговування;
- ремонти та заміну запчастин;
- витрати;
- документи;
- нагадування про майбутнє обслуговування;
- основну інформацію про автомобіль;
- статистику витрат;
- пошук по сервісній історії.
- деталізацію ремонту: якщо вибрано «Інше», можна вказати, що саме ремонтували або замінили.

---

# 🎯 Мета проєкту

Створити зручну цифрову систему, яка дозволяє:

1. Додати один або декілька автомобілів.
2. Зберігати інформацію про кожен автомобіль.
3. Вести повну історію ремонту та технічного обслуговування.
4. Контролювати витрати на автомобіль.
5. Зберігати документи.
6. Створювати нагадування про майбутні роботи.
7. Переглядати статистику.
8. Отримувати доступ до власних даних з акаунта.

У майбутньому CarMemory має перетворитися з локального прототипу на повноцінний вебсервіс із авторизацією та хмарною базою даних.

# 💾 Поточне збереження даних

Поточний прототип використовує:

```javascript
localStorage
```

для збереження даних у браузері.

Це дозволяє зберігати:

- автомобілі;
- сервісні записи;
- документи;
- нагадування;
- вибраний автомобіль.

Але `localStorage` не підходить як основне сховище для повноцінного сервісу.

Основні проблеми:

- дані зберігаються тільки на конкретному пристрої;
- немає нормальної авторизації;
- немає синхронізації між пристроями;
- немає надійної серверної бази;
- файли документів фактично не зберігаються у хмарі.

Тому наступний етап — перенесення даних у backend.

Основна структура:

```text
                 ┌──────────────┐
                 │    User      │
                 └──────┬───────┘
                        │
                        │ user_id
                        ↓
                 ┌──────────────┐
                 │     Cars     │
                 └──────┬───────┘
                        │
             ┌──────────┼──────────┐
             ↓          ↓          ↓
        ┌────────┐ ┌─────────┐ ┌──────────┐
        │Services│ │Expenses │ │Documents │
        └────────┘ └─────────┘ └──────────┘
                        │
                        ↓
                  ┌───────────┐
                  │ Reminders │
                  └───────────┘
```

Таким чином один користувач може мати багато автомобілів, а кожен автомобіль — власну історію.

# 🔒 Row Level Security

Для захисту даних планується використовувати **Row Level Security (RLS)**.

Основний принцип:

```text
User A
   ↓
бачить тільки свої автомобілі
   ↓
бачить тільки свої сервіси
   ↓
бачить тільки свої документи
   ↓
бачить тільки свої витрати


User B
   ↓
бачить тільки свої дані
```

Користувач не повинен мати можливості отримати записи іншого користувача простим зміною `id`.

---

# ☁️ Зберігання документів

Для документів планується використати Supabase Storage.

Архітектура:

```text
Користувач
    ↓
Upload PDF / JPG / PNG
    ↓
Supabase Storage
    ↓
file_url
    ↓
documents
```

У базі даних буде зберігатися інформація про файл, а сам файл — у Storage.

## 🚀 Наступний крок

Після цього README логічно перейти до реалізації **Етапу 3–4**:

1. Створити Supabase project.
2. Підключити Supabase до CarMemory.
3. Зробити сторінку «Вхід / Реєстрація».
4. Реалізувати logout та перевірку сесії.
5. Створити таблиці PostgreSQL.
6. Додати `user_id` до всіх персональних даних.
7. Налаштувати RLS.
8. Перенести автомобілі, сервіс, витрати, документи та нагадування з `localStorage` у базу.
9. Зробити так, щоб кожен користувач бачив тільки власні дані.
10. Підключити Supabase Storage для реальних PDF/фотографій документів.
